# [B-001.7] Añadir documentación mínima de instalación y arranque

## Descripción

Documentar el procedimiento para que otra persona pueda preparar y arrancar el proyecto sin explicaciones adicionales.

## Contenido mínimo

1. Requisitos previos.
2. Preparación de `.env` desde `.env.example`.
3. Construcción de imágenes.
4. Arranque de servicios.
5. URLs locales.
6. Detención de servicios.
7. Validaciones básicas.

## Criterios de aceptación

- [x] Los pasos parten desde la raíz del repositorio.
- [x] Se explica cómo crear `.env` sin incluir secretos.
- [x] Se documentan `docker compose build`, `up` y `down`.
- [x] Se documentan las URLs locales.
- [x] Se explica cómo ejecutar las validaciones básicas.
- [x] Otra persona puede repetir el arranque siguiendo únicamente la documentación.
- [x] No se duplica información que corresponde a `PLAN.md` o `ARCHITECTURE.md`.

## Dependencias

Depende de **B-001.1** a **B-001.6**.

## Evidencia de cierre

Se creó [`docs/GETTING_STARTED.md`](../../docs/GETTING_STARTED.md) con:

- requisitos previos;
- creación de `.env` desde `.env.example`;
- validación segura de Compose;
- construcción y arranque de imágenes;
- URLs locales y healthcheck;
- validaciones opcionales de backend y frontend;
- detención de servicios;
- problemas frecuentes.

La guía utiliza el flujo Docker validado en B-001.6 y evita repetir el contexto de producto de `README.md`, el cronograma de `PLAN.md` y la estructura técnica de `ARCHITECTURE.md`.
