# [B-033.7] Identificación de reproducciones (runs) y memoria comprimida para el evaluador

**Estado:** planificada (2026-11-14). Padre: **B-033** ([#110](https://github.com/andrupax94/PianoMentor-IA/issues/110)). Hermana de B-033.4 (interpretación) y B-033.6 (paquetes importados). Nace de la observación de que el informe JSON de B-033.3 acumula todas las señales de la sesión sin distinguir pasadas, por lo que reiniciar la pieza y volver a tocar hace crecer el informe indefinidamente y el evaluador no puede comparar intentos.

## Descripción

Hoy una sesión es un contenedor append-only de señales (`practice_signals`). Reiniciar la reproducción no crea una sesión nueva, pero las señales de la nueva pasada se mezclan con las anteriores y el informe (`build_report`) agrega todo sin separar. Como consecuencia:

- El JSON del informe crece cada vez que se toca la pieza (más entradas en `by_measure`, más `arrival`, mayor `signal_count`).
- El evaluador no puede saber qué señal pertenece a qué reproducción ni emitir frases del tipo «esta pasada salió mejor que las anteriores» o «en el compás X fallaste antes y ahora acertaste».

Esta sub-issue introduce el concepto de **pasada (run)** dentro de la sesión y una **memoria comprimida** de las pasadas previas para el evaluador, manteniendo el informe completo solo para la pasada actual.

## Alcance

### 1. Identificación de reproducciones (run)

- **Migración** `0016_add_run_to_practice_signals` (y campo `current_run` en `sessions`): añadir `run_id INTEGER NOT NULL DEFAULT 1` a `practice_signals`. Sesiones antiguas sin run se tratan como run 1 (fallback en DB y en `build_report`).
- **Trigger de nueva pasada:** solo un reinicio explícito incrementa el run; el avance normal del transporte no. Opciones:
  - evento `practice` con `outcome: "restart"` emitido por el frontend al reiniciar la pieza, o
  - endpoint `POST /sessions/{id}/runs` que incrementa `current_run`.
- Cada `receive_practice_event` persiste la señal con el `run_id` vigente de la sesión.
- `build_report` acepta `run` (opcional, por defecto el último) y agrega solo las señales de esa pasada. Añade además un bloque `runs: [{run_index, signal_count, ...}]` con el resumen de cada pasada.

### 2. Evaluador: pasada actual completa + histórico comprimido

- El informe que consume el evaluador entrega dos bloques:
  - **Pasada actual (extendido):** el reporte completo de la última pasada (por compás, arrival, counts, señales truncadas), igual que hoy.
  - **Pasadas previas (comprimido):** un resumen determinista por run, p. ej. `{run, measures_with_errors, total_hits, total_misses, trend}`. Sin señales crudas ni arrivals.
- El histórico se limita a las últimas N pasadas (p. ej. 5); el resto se resume en un agregado global, para no inflar el prompt.

### 3. Comparación determinista (no LLM)

- El backend calcula un bloque `comparison` (delta de hits/misses respecto a la mejor pasada anterior, compases que mejoraron/empeoraron). El LLM solo lo verbaliza; no recalcula. Mantiene el motor musical determinista separado del LLM (regla del proyecto).
- Esto habilita frases del tipo «lo que acabas de tocar está mejor que en tus anteriores intentos» o «cometiste fallos en el compás X en intentos anteriores; ahora te salió mejor, intenta relajar las manos».

### 4. Compatibilidad

- `signal_count` global de la sesión se conserva (compatibilidad con tests existentes de B-033.3), añadiendo `run_signal_count` para la pasada actual.
- `session-interpreation` (B-033.4) y el pipeline de paquetes importados (B-033.6) deben seguir funcionando: si no hay `run_id`, se asume run 1.

## Decisiones

- **El punto de inyección del reinicio es el transporte/frontend**, igual que el resto de eventos de práctica (B-032.2). El backend no infiere pasadas a partir de la posición del transporte.
- **El evaluador no recalcula métricas:** solo verbaliza el `comparison` determinista y el resumen comprimido.
- **Determinismo estricto:** misma sesión + mismos datos → mismo informe (orden estable por `id`), incluyendo el bloque `comparison`.

## Dependencias

- B-033.3 (informe de sesión), B-033.4 (interpretación), B-033.6 (paquetes importados: un informe importado también informa una pasada), B-032.6 (señales de práctica), B-032.5 (gates).
