# [B-024.1] Guion, storyboard y reglas editoriales del vídeo

**Estado:** planificada (2026-11-15). Padre: **B-024** (#26).

## Objetivo

Escribir el guion completo del vídeo antes de grabar nada, en `docs/DEMO_VIDEO.md`, con el mismo formato que `docs/DEMO_AGENT.md`: qué se dice, qué se ve, qué debe pasar y qué mirar si falla.

## Alcance

1. **Guion literal de la voz en off**, capítulo a capítulo, con el texto de intro y cierre (≤ 60 palabras cada uno).
2. **Shot list**: por cada toma, URL, clics, teclas, resultado esperado y duración.
3. **Tabla `claim → evidencia`**: cada afirmación con su archivo, test, issue o ADR. Ejemplos:
   - «El LLM no toca el reloj» → `websocket-client.ts`, `agent-playback.ts`.
   - «Lista blanca de 12 funciones» → `tools.py`, `test_agent.py`.
   - «Funciona sin LLM» → cadena Groq → Gemini → Mock.
   - «La demo se ofrece, no se impone» → ADR 0008, `agent-offer.ts`.
4. **Las tres tarjetas problema → solución**, con la evidencia que se enseña en pantalla:
   - dos relojes → transporte único (B-032.2);
   - la IA no puede decidir con latencia → reglas deterministas + LLM solo para lenguaje (B-012, B-032.6);
   - el informe confundía unidades y salía con la sesión viva → sesión terminal, unidades explícitas e instrumentación del canal (B-033.8/B-033.9).
5. **Plan B por toma**: qué hacer si el LLM tarda, si el backend está dormido o si la pieza no carga.

## Criterios de aceptación

- [ ] `docs/DEMO_VIDEO.md` existe con las cinco secciones anteriores.
- [ ] El guion se lee cronometrado en ≤ 4:15.
- [ ] Cada claim visible tiene su fila de evidencia.
- [ ] La intro y el cierre caben en ~20 s cada uno.
- [ ] El texto evita claims no implementados (micrófono, telemetría acústica, hardware MIDI).

## Dependencias

B-024. Nada que ver con el motor: es documentación y guion.
