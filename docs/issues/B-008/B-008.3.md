# [B-008.3] Compás actual en el PlayerBar

**Estado:** finalizada (2026-10-16).

## Descripción

`TempoMeasure` muestra hoy `Tempo: 60 BPM` y `Measure: 12/16` como defaults de mentira; el BPM es real desde B-007.3, pero el compás sigue falso porque la app no tiene rejilla. Esta sub-issue sirve la rejilla de B-008.1 al front y hace que el PlayerBar muestre el compás real durante la reproducción.

## Alcance

- Decidir y documentar cómo viaja la rejilla al front (extender la respuesta de `GET /pieces/{id}/notes` o endpoint propio), con «el motor decide, el front consulta» como criterio.
- Derivar el compás actual de `position_s` con búsqueda binaria sobre la rejilla, sin añadir relojes ni timers nuevos (misma cadencia de 25 ms que resaltado y barra de progreso).
- `TempoMeasure` pinta firma y compás actual/total —hay que definir etiquetas: hoy «Measure» es la firma falsa, y hay que separar firma de contador— y **elimina los defaults de mentira** `60`/`12/16`: sin datos se muestra indicador vacío (`–`), como ya hace el tempo.
- Comportamiento temporal heredado de `position_s`: en pausa el compás no se mueve; con factor de tempo escala igual que el audio y la cascada (B-007.3).
- Tests front con reloj falso: cruzar un borde de compás actualiza el índice; sin rejilla, indicador vacío.

## Criterios de aceptación

- [x] Durante la reproducción, el PlayerBar muestra el compás actual real y lo actualiza al cruzar de compás.
- [x] No queda ningún `Measure: 12/16` ni `60 BPM` de mentira en props o defaults.
- [x] En pausa el compás no avanza; con factor de tempo distinto de 1 avanza en coherencia con el audio.
- [x] Sin pieza cargada o sin rejilla se muestra indicador vacío, nunca un valor inventado.
- [x] `npm test -- --run` pasa y `npm run build` compila.

## Decisiones de implementación

- **La rejilla viaja en la propia respuesta de `GET /pieces/{id}/notes`** (campo `measures`), no en un endpoint propio. Motivo: el front ya pide la partitura una sola vez al cargar la pieza; añadir la rejilla evita un segundo viaje y mantiene «el motor decide, el front consulta». El contrato es `PieceMeasures { count, starts_s, signatures, end_s }`, con `signatures` alineada con `starts_s`.
- **El compás actual se deriva con una función pura**, `frontend/src/lib/measures.ts` (`measureIndexAt`), mediante búsqueda binaria sobre `starts_s`. `position_s` va en segundos de partitura ya escalados por el factor de tempo (misma línea temporal que la cascada y el audio), así que se compara `position_s × factor` contra los inicios originales. No se añaden relojes ni timers: se recalcula en cada render del tick de 25 ms del transporte.
- **Etiquetas separadas**: `TempoMeasure` pinta `Tempo:` (BPM), `Compás:` (actual/total, 1-based) y `Firma:` (n/d). Se eliminan los defaults falsos (`60`, `12/16`); sin datos se muestra `–`.
- **Bordes coherentes con el backend**: en un borde exacto el índice pasa al compás que empieza ahí, igual que `MeasureGrid.measure_at`.
- **Refactor del endpoint**: se construye la rejilla una sola vez (una lectura) y sirve tanto la ventana de compases (B-008.2) como la respuesta al front, eliminando la doble consulta a la base de datos.
