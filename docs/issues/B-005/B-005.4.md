# [B-005.4] Integrar metadatos musicales en la carga y verificar el flujo

## Descripción

Conectar el motor normalizado con la carga de piezas para que, al subir un MIDI, los campos musicales (`tracks`, `duration_seconds`, `tempo`, `notes_count`) se calculen, persistan en SQLite y se devuelvan al frontend, que ya sabe mostrarlos.

## Alcance

- Invocar `MidiService.inspect_file` desde el flujo de `POST /api/v1/pieces` una vez guardado el archivo en filesystem.
- Persistir los campos musicales en la tabla `pieces` (`tracks`, `duration_s`, `notes_count`) sin romper el esquema existente de B-003.1; añadir migración si se decide persistir también tempo.
- Devolver esos campos dentro de `metadata` en `PieceResponse`, cumpliendo el contrato de B-002.1 tal como lo refleja `schemas.py`.
- Definir el comportamiento cuando el parsing musical falla tras haber guardado el archivo: decidir y documentar si la carga se rechaza (500 con código estable) o se acepta con metadatos nulos.
- Verificar el flujo end-to-end con Docker: subir un MIDI del corpus desde la web y ver tracks, duración y número de notas en pantalla.
- Actualizar los tests de carga para cubrir el caso con metadatos rellenados.

## Criterios de aceptación

- [ ] Tras cargar un MIDI válido, la respuesta incluye tracks, duración y número de notas reales.
- [ ] Los valores persistidos son consultables en SQLite tras el arranque.
- [ ] La web muestra esos metadatos sin cambios adicionales en el frontend.
- [ ] Un fallo de parsing se comunica con un código de error estable, sin trazas expuestas.
- [ ] El flujo funciona en Docker Compose: subir un MIDI del corpus y ver sus metadatos.
- [ ] `python -m pytest -q` pasa (60 tests existentes más los nuevos) y el healthcheck continúa en verde.

## Dependencias

Depende de **B-005.1**, **B-005.2** y **B-005.3**. Cierra **B-005** y habilita a **B-006**, **B-008** y **B-013**.

## Evidencia esperada

- Carga con metadatos musicales persistidos, captura de la web mostrándolos y verificación del flujo con Docker.
