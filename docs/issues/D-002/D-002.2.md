# [D-002.2] Transparencia progresiva de las barras de la cascada

**Estado:** implementado y verificado en local (2026-10-25); pendiente de commit.

## En palabras simples

Ahora las notas aparecen de golpe en el borde superior de la cascada y desaparecen de golpe al llegar al teclado. Con este cambio **entran invisibles y se van materializando a medida que bajan**, hasta quedar del todo opacas justo sobre las teclas. El efecto se aplica solo a las barras: la rejilla de fondo no se toca.

## Descripción

La idea original era superponer un `div` de toda la cascada con un gradiente de color de fondo arriba a transparente abajo. El problema es que ese div taparía también las líneas de la rejilla y las etiquetas de octava. La solución no es un div encima, sino una **máscara** sobre el propio contenedor de las notas.

## Alcance

1. **Máscara en `.notes`** (`NoteFallGrid.module.css`). El contenedor `.notes` es el único que contiene bloques y es **hermano** de `.lines` (la rejilla), así que lo que se atenúe ahí no afecta a nada más:

   ```css
   .notes {
     position: absolute;
     inset: 12px;
     overflow: hidden;
     pointer-events: none;
     /* Arriba invisible → opaco al 70 %; el último tramo queda plano para que la
        nota aterrice a plena opacidad sobre la línea del teclado. */
     -webkit-mask-image: linear-gradient(to bottom,
         rgba(0, 0, 0, 0) 0%,
         rgba(0, 0, 0, 1) 70%,
         rgba(0, 0, 0, 1) 100%);
     mask-image: linear-gradient(to bottom,
         rgba(0, 0, 0, 0) 0%,
         rgba(0, 0, 0, 1) 70%,
         rgba(0, 0, 0, 1) 100%);
     mask-repeat: no-repeat;
     -webkit-mask-repeat: no-repeat;
   }
   ```

2. **Ajuste de las paradas** hasta que la nota ya se vea bien entrada antes de tocar el teclado: el 70 % es una propuesta, no un dogma. El criterio es que el último tramo (el que queda sobre la línea `.final__line`) esté a opacidad completa.

3. **Comprobación de rendimiento** con una pieza densa (acordes, B-009): una máscara convierte el contenedor en una capa compuesta. Verificar que el bucle rAF sigue a 60 fps y que no aparece un repaint por frame.

## Decisiones

### 1. Máscara en el contenedor, no div superpuesto

- No añade DOM ni `z-index`.
- `.lines` (rejilla), `.side` (etiquetas de octava) y `.final__line` quedan intactos porque son hermanos de `.notes`, no hijos.
- El gradiente recorre toda la cascada de golpe: si se aplicara un gradiente por bloque (`background` de cada barra), cada nota llevaría su propio degradado y una nota larga saldría a rayas. La máscara del contenedor mapea **posición en pantalla**, que es justo lo que se quiere.

### 2. Dirección del efecto

**Arriba transparente → abajo opaco** (confirmado con el usuario). Las notas se materializan al acercarse, como en Synthesia. La dirección contraria (se desvanecer justo antes del teclado) quedó descartada.

### 3. Se multiplica con la opacidad por velocity

Cada bloque ya lleva `opacity` por sonoridad (`noteOpacity()` → 0.35–0.85) y la máscara se aplica encima: una nota suave arriba es doblemente tenue. Es el resultado esperado, no un bug.

### 4. Prefijo `-webkit-`

Se escribe `mask-image` y `-webkit-mask-image` juntos por Safari.

## Fuera de alcance

- Mover o recolorear la rejilla, las etiquetas de octava o `.final__line`.
- Cambiar `noteOpacity()` ni la velocidad de caída.
- Atenuar el teclado o la partitura.

## Verificación en vivo (2026-10-25)

Con la demo p17 (Beethoven — Symphony No. 5) en `localhost:3000`:

- **Máscara aplicada solo a `.notes`:** `mask-image` computado = `linear-gradient(rgba(0, 0, 0, 0) 0%, rgb(0, 0, 0) 70%, rgb(0, 0, 0) 100%)`; `.lines` = `none`. La rejilla, las etiquetas de octava (C1/C2/C3) y `.final__line` se ven idénticas a antes.
- **Efecto a la vista:** 28–32 bloques en pantalla, entrando casi invisibles por arriba y llegando opacos al teclado. Confirmado por el usuario: *"sí se ve la transparencia"*.
- **En pausa:** los bloques quedan congelados (mismas coordenadas en dos lecturas separadas) y **conservan** la atenuación: la máscara depende de la posición, no del tiempo. `mask-image` sigue computándose igual con 28 bloques.
- **Rendimiento:** contador de `requestAnimationFrame` durante 52,6 s → **2.985 frames ≈ 57 fps** de media con la pieza densa; el mayor salto (800 ms) coincide con la actividad de las herramientas del navegador (capturas/evaluaciones), no con la máscara.
- **Sin DOM nuevo ni `z-index`:** solo cambian las reglas de `.notes`; el HTML del componente no se tocó.
