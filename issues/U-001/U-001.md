# [U-001] Configurar el depurador en VS Code y Docker

**Estado:** implementado en local; pendiente de verificación en Docker y de commitear `docker-compose.debug.yml`.

## Resumen

Poder depurar el backend (Python/FastAPI) y el frontend (Next.js/Vitest) desde VS Code, tanto corriendo fuera de Docker como dentro, con puntos de ruptura, inspección de variables y la opción de adjuntar a un proceso que ya esté en marcha.

## Objetivo

Que depurar sea un F5 y no un arte: el backend se depura con `debugpy`, el frontend con `node --inspect`, y ambos se alcanzan desde VS Code sin tener que recordar comandos ni puertos cada vez.

## Alcance

- **Lanzamiento fuera de Docker (local):**
  - Backend: dos configs de arranque con `uvicorn` (uno con `--reload` para desarrollo, otro sin recarga para depurar limpio) usando el Python real del proyecto `E:\Python312\python.exe` (3.12, con `fastapi`/`uvicorn`). Se fuerza ese intérprete porque `uv` tiene un 3.14 sin `uvicorn` que VS Code tiende a elegir solo.
  - Front Next.js (`next dev`) y Vitest (`npm test`).
  - `pytest` para el backend.
  - Chrome para depurar el front en el navegador.
- **Lanzamiento/adjunte en Docker:**
  - `docker-compose.debug.yml` (se apoya en `docker-compose.yml`): backend con `debugpy` escuchando en el puerto **5678** y front con `node --inspect` en el **9229**, ambos en `0.0.0.0` para que VS Code les llegue desde Windows.
  - Configs de tipo *attach* en VS Code para adjuntarse a esos puertos.
- **Configuración de VS Code:** `.vscode/launch.json` (configs de arranque y adjunte), `.vscode/settings.json` (intérprete de Python fijado al 3.12) y `.vscode/extensions.json` (extensiones recomendadas).
- `.vscode/` queda en `.gitignore` (configuración local de cada máquina); `docker-compose.debug.yml` sí es commiteable.

## Fuera de alcance

- Cambiar la configuración de ejecución en producción (`docker-compose.yml` normal).

- Otros lenguajes o runtimes distintos de Python y Node.
