# [B-003.1] Instalar SQLite + sqlite-vec y esquema base de piezas

**Estado:** completada (2026-10-16). sqlite-vec se instala y se carga al abrir la conexión, y el esquema de `pieces` se crea desde migraciones SQL versionadas e idempotentes.

## Descripción

Instalar la extensión sqlite-vec, crear `database.py` con una conexión reutilizable y definir el esquema base para piezas y vectores.

## Alcance

- Añadir la dependencia sqlite-vec al backend (y a la imagen Docker).
- Cargar la extensión al abrir la conexión SQLite.
- Reutilizar `DATABASE_URL` de la configuración existente (`config.py`).
- Crear `backend/src/piano_mentor/database.py` con funciones de conexión y creación de esquema.
- Tabla `pieces`: `id`, `filename`, `stored_filename`, `size_bytes`, `extension`, `tracks`, `duration_s`, `notes_count`, `created_at`.
- Tabla `piece_vectors`: `piece_id` (FK a `pieces`), `embedding` (vector sqlite-vec, nullable hasta que B-005/B-013 definan las features).
- Documentar el esquema (migración mínima o script de init versionado).

## Implementado

- `sqlite-vec>=0.1.9,<1.0` está en `backend/pyproject.toml` y en `backend/Dockerfile`; `database.connect()` abre SQLite con `enable_load_extension`, carga la extensión y devuelve filas como `sqlite3.Row`.
- El esquema vive en `backend/src/piano_mentor/migrations/*.sql` y se aplica con `init_db()`, que registra cada versión en `schema_migrations` (reproducible e idempotente). La migración `0001_init_pieces.sql` crea `pieces` con los metadatos del catálogo (`midi_path`, `title`, `composer`, `opus`, `license`, `source_url`, `difficulty`…) y un índice por compositor; las migraciones posteriores añaden `tempo` (0002), `content_hash`/`source`/`owner_id` (0003) y `cover` (0004).
- **No se creó `piece_vectors`**: los embeddings no tienen features todavía, así que la tabla vectorial queda para cuando B-005/B-013 las definan. Ninguna pieza depende de un embedding para existir.
- Tests en `backend/tests/test_database.py`: conexión desde `DATABASE_URL`, versión de sqlite-vec cargada, filas tipo diccionario, creación del directorio padre, rechazo de URLs no SQLite, esquema de `pieces` con campos musicales opcionales, ausencia de tablas de sesiones e idempotencia de las migraciones.

## Criterios de aceptación

- [x] La extensión sqlite-vec se carga sin errores en local y en Docker (probado por `test_sqlite_vec_extension_loaded`).
- [x] Existe una función de conexión reutilizable por otros módulos (p. ej. B-012): `database.connect()`.
- [x] La tabla `pieces` se crea de forma reproducible desde migraciones versionadas (`schema_migrations`); la tabla `piece_vectors` queda aplazada a B-005/B-013.
- [x] Los vectores son opcionales: hoy ninguna pieza requiere un embedding para existir.
- [x] Existen tests de conexión, carga de la extensión y creación del esquema (`backend/tests/test_database.py`).
- [x] No se crean tablas de sesiones (reservadas para B-012), verificado en los tests.
