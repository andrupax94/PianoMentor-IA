# [B-002] Preparar contrato y almacenamiento base de piezas MIDI

## Resumen

Preparar los contratos y límites técnicos que necesita la carga de piezas MIDI, sin duplicar el healthcheck y el arranque FastAPI ya resueltos durante B-001.

## Objetivo

Dejar definida una base estable para que B-003 implemente `POST /api/v1/pieces` con validación, almacenamiento local y respuesta de metadatos sin acoplar el endpoint a detalles concretos del filesystem.

## Sub-issues

- [B-002.1 — Definir el contrato de piezas MIDI](B-002.1.md)
- [B-002.2 — Preparar almacenamiento local de piezas MIDI](B-002.2.md)
- [B-002.3 — Definir límites y seguridad de cargas MIDI](B-002.3.md)
- [B-002.4 — Preparar fixtures y pruebas para la carga MIDI](B-002.4.md)

## Alcance

- Definir el modelo de pieza y la respuesta mínima de la API.
- Definir la abstracción inicial de almacenamiento de archivos MIDI.
- Usar `MIDI_STORAGE_PATH` como ubicación configurable.
- Crear la carpeta de almacenamiento si no existe cuando corresponda.
- Definir límites iniciales de extensión y tamaño.
- Evitar sobrescribir archivos mediante nombres o identificadores estables.
- Preparar fixtures y tests de contrato para B-003.
- Mantener el almacenamiento local como implementación del MVP.

## Fuera de alcance

- Parsing MIDI completo.
- Normalización de notas, tempo o compases.
- Reproducción musical.
- Evaluación de interpretaciones.
- Persistencia histórica de sesiones.
- Integración con LLM.

## Criterios de aceptación

- [ ] Existe un contrato tipado para una pieza cargada y sus metadatos iniciales.
- [ ] Existe una interfaz o límite claro entre el caso de uso y el almacenamiento de archivos.
- [ ] La ruta de almacenamiento se obtiene de configuración y no está hardcodeada en el caso de uso.
- [ ] Se definen extensiones aceptadas (`.mid` y `.midi`) y un límite inicial de tamaño.
- [ ] Los nombres de archivos de usuario no permiten traversal ni sobrescritura accidental.
- [ ] Hay tests para el contrato, la configuración y el almacenamiento local.
- [ ] B-003 puede implementar `POST /api/v1/pieces` sobre esta base sin redefinir los contratos.
- [ ] El healthcheck existente continúa funcionando.

## Dependencias

Depende de **B-001**. Es prerequisito de **B-003**.

## Evidencia esperada

- Modelos o esquemas tipados definidos.
- Implementación local de almacenamiento probada.
- Fixture MIDI y tests de contrato.
- Configuración reproducible mediante Docker y ejecución local.
