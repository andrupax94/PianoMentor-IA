# [B-004.3] Manejar errores de carga y verificar el flujo end-to-end

## Descripción

Asegurar que cualquier fallo de la carga se comunica de forma entendible en la web y verificar el flujo completo seleccionar → subir → ver metadatos contra el backend real en Docker.

## Alcance

- Mostrar los errores del backend traducidos: 400 (`validation_*`) y 500 (`persistence_error`) con su `message`, sin exponer trazas.
- Manejar el caso de backend caído o sin red: mensaje de "servicio no disponible" sin romper la página.
- Añadir estado vacío y limpiar el error al seleccionar un archivo nuevo.
- Comprobar el flujo end-to-end con Docker Compose (`docker compose up`) subiendo un MIDI del corpus y uno inválido.
- Tests del cliente: al menos un test de `uploadPiece` con éxito y uno con error 400 (con `fetch` simulado).
- Documentar en `docs/GETTING_STARTED.md` el flujo web de carga una vez verificado (apartado breve).

## Criterios de aceptación

- [x] Un archivo inválido muestra el mensaje del backend, sin excepción ni pantalla en blanco.
- [x] Con el backend detenido, la web muestra un error controlado y sigue siendo navegable.
- [x] El error desaparece al cargar un archivo válido después de uno inválido.
- [x] Existen tests del cliente para éxito y fallo 400.
- [x] El flujo completo funciona en Docker: subir un MIDI del corpus y ver sus metadatos.
- [x] El healthcheck del backend continúa en verde y los 60 tests de backend no se ven afectados.

## Dependencias

Depende de **B-004.2**. Cierra **B-004**.

## Evidencia esperada

- Capturas de error controlado, tests del cliente y verificación del flujo con Docker.
